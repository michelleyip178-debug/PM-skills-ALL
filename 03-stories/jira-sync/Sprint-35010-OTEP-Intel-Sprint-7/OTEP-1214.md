The 11 "data analysis" bullets (the person's actual core job) aren't surfacing their best competency match ("Exploration Analysis" only shows up via the tools section, not via any of the actual analysis work).  Root cause: The reranker prompt (reranker_v1.txt) gives zero guidance on disambiguation. It says "Choose the single best-fitting candidate" but never instructs the model to: Read the candidate's definition before matching Distinguish between a keyword appearing as part of someone's ACTIVITY vs as the SUBJECT of the competency Consider whether the chunk's actual work aligns with the competency definition  The model already sees definitions in the user message (_format_candidates renders area/competency/definition atsrc/cie/inference/pipeline/rerank.py:250-263) but has no instruction to use them.   Changes Create src/cie/prompts/reranker_v2.txt  New prompt file. Same output JSON schema. Key additions to the Rules section:  Disambiguation guidance (addresses the precision failures): Match on what the person DID (the activity in the chunk), not on proper nouns or framework names mentioned inpassing. Example: "Drafted contributions for the Data Governance Framework" is a writing/policy activity, not data governance work. Read each candidate's definition before choosing. The best match is the candidate whose definition describes the ACTIVITY shown in the chunk, not the one whose name shares keywords with the chunk. A keyword appearing in the chunk does not mean the competency with that keyword is the right match. The person must be PERFORMING that competency, not merely referencing it. When uncertain, prefer a lower confidence over a high-confidence wrong match.  All existing rules preserved verbatim: single candidate only, verbatim evidence substring, confidence calibration, reject-if-none, exact JSON output shapes.
