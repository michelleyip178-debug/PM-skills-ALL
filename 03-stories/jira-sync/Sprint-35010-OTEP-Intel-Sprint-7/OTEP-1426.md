# OTEP-1426: Migrate ALB source IP whitelisting from NACL/SG to WAF IP sets

## Description

Context The internal ALB ( cie-internal-alb ) currently enforces source IP whitelisting at two layers: ALB Security Group  — specific AIAP CIDR ingress rules ( 10.80.145.224/28 ,  10.80.145.240/28 ) ALB subnet NACL  — rule 260 allowing all traffic from  10.0.0.0/8 As more consumers connect via TGW, maintaining per-source CIDR rules in SGs and NACLs becomes unscalable and operationally fragile (SG limits, NACL rule ordering, multiple places to update). Proposed approach WAF IP set  — create a WAF IP set ( cie-alb-allowed-sources ) containing all authorized source CIDRs. Add a WAF rule with priority higher than the existing managed rules that blocks any request not originating from the IP set. ALB SG  — broaden to allow  10.0.0.0/8  (or the full intranet range). The SG becomes a network reachability gate only, not an access control layer. ALB NACL  — keep coarse deny rules (SSH/RDP) + allow-all for legitimate traffic ranges. Remove any fine-grained source whitelisting. Benefits Single place to manage access (WAF IP set) Scalable to 10,000 CIDRs per set WAF metrics and sampled requests for visibility into blocked traffic No SG rule explosion as consumers grow Cleaner separation: NACL = L3/L4 coarse filter, SG = VPC reachability, WAF = application-level access control Acceptance criteria [ ] WAF IP set created with AIAP NPRD/PRD egress CIDRs [ ] WAF rule blocks requests from IPs not in the set (default deny) [ ] ALB SG broadened to  10.0.0.0/8 [ ] ALB NACL simplified (no per-source whitelisting) [ ] Propagated to all environments (dev/qa/preprod/prd) [ ] Existing AIAP connectivity verified post-change
