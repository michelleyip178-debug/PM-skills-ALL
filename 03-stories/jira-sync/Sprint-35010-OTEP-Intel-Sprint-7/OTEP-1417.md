# OTEP-1417: Eliminate provider cache race condition in run-all jobs in IaC

## Description

Problem terragrunt run --all jobs (validate, plan, apply) are flaky due to a race condition in the shared Terraform provider cache. Root cause .tg-base sets TF_PLUGIN_CACHE_DIR="/tmp/terraform-providers" so 35+ stacks share one provider download instead of each downloading ~150MB independently (which caused disk exhaustion - the original OTEP-1404 fix). However, run --all spawns multiple terraform init processes concurrently, and they all race to populate the cache simultaneously: Process A starts writing terraform-provider-aws_v5.x to the cache Process B sees the file (partially written), symlinks it into its own .terraform/ Process B tries to execute a truncated/incomplete binary - crash TF_PLUGIN_CACHE_MAY_BREAK_DEPENDENCY_LOCK_FILE=1 (added in the follow-up commit) only suppresses lock file hash validation - it does NOT fix the concurrent-write race. Evidence MR !107 pipeline #252: validate:dev (35 stacks) failed while validate:qa, validate:preprod, validate:prd (fewer stacks = lower contention) all passed in the same run The pattern is non-deterministic - same code passes on retry, classic race symptom  Solution Pre-warm the cache (single-process init before run-all) Add a pre-warm step to .tg-base before_script that downloads all providers before any concurrent work begins. After pre-warm completes, cache files are fully written and immutable - subsequent terraform init calls only create symlinks (atomic on Linux, safe under any concurrency). |  WARMUP_DIR=$(mktemp -d)  cat > "$WARMUP_DIR/main.tf" <<'TF'  terraform {    required_providers {      aws     = { source = "hashicorp/aws", version = "~> 5.0" }      archive = { source = "hashicorp/archive", version = ">= 2.4" }      random  = { source = "hashicorp/random", version = ">= 3.5" }    }  }  TF  terraform -chdir="$WARMUP_DIR" init -backend=false -input=false >/dev/null 2>&1 || true  rm -rf "$WARMUP_DIR" Providers used across stacks: hashicorp/aws (~150MB) - all stacks hashicorp/archive (~15MB) - opensearch-migrator, nightly-eval-scheduler hashicorp/random (~12MB) - opensearch-cluster, grafana-workspace Cap run-all parallelism at 4 Add --parallelism 4 to all terragrunt run --all commands to prevent thundering-herd on the runner (memory, S3 state reads, STS calls). Why no retry Pre-warm creates a strict happens-before between cache writes and cache reads. The race window is zero. retry: when: script_failure would mask real validation errors and double time-to-signal.  Affected jobs All jobs extending .tg-base: validate: , plan: , apply:* Acceptance criteria [ ] Pre-warm step added to .tg-base before_script [ ] All terragrunt run --all commands use --parallelism 4 [ ] Pipeline passes on first attempt without cache-related errors
