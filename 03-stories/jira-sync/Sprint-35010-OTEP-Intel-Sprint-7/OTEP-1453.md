# OTEP-1453: WAF SizeRestrictions_BODY blocks AIAP CV uploads to MCP inference endpoint

**Status:** Backlog
**Assignee:** Brian Noel Kesuma
**Story Points:** N/A
**Sprint:** OTEP-Intel Sprint 7 (35010)

## Description

Problem The AIAP competency review MCP client sends  POST /inference  requests with CV payloads (~60KB) as multipart form data. The AWS WAF  AWSManagedRulesCommonRuleSet  includes a  SizeRestrictions_BODY  rule with a hard 8KB limit. This results in a 403 Forbidden response before the request can reach the MCP backend service. This was identified in the  dev  environment via WAF sampled requests, which showed all blocked requests matched this rule with body sizes around 61KB. Root Cause The WAF web ACL applies the full  AWSManagedRulesCommonRuleSet  without any rule overrides. The default 8KB hard limit on request bodies is fundamentally incompatible with the expected CV file upload sizes. Fix Rule Override:  Updated the shared WAF module ( module/compute/waf/main.tf ) to override  SizeRestrictions_BODY  from  BLOCK  to  COUNT . Oversized requests are now permitted to pass but are still logged via CloudWatch metrics for visibility. Environment Rollout:  Deployed WAF stacks to  qa ,  preprod , and  prd  environments (previously only provisioned in  dev ). All environments now share the updated WAF configuration. Impact All other standard OWASP rules (XSS, path traversal, Log4j, SQL injection, etc.) remain fully enforced in  BLOCK  mode. Because  SizeRestrictions_BODY  operates in  COUNT  mode, we retain visibility into payload sizes. If abuse occurs, we can deploy a custom size limit rule with a specifically tuned higher threshold (e.g., 2MB). Environments Affected:   dev ,  qa ,  preprod ,  prd Verification Steps Run  terragrunt plan  in  live/<env>/edge/waf/  for each environment.  dev  will show an in-place update; others will show new resource creation. After applying the changes in  dev , have the AIAP team re-test the  POST /inference  CV upload. Verify the endpoint returns a  200 OK  instead of  403 . Check WAF sampled requests in the AWS Console to confirm that oversized requests trigger a  COUNT  action for  SizeRestrictions_BODY  rather than a  BLOCK . Acceptance Criteria [ ] WAF  SizeRestrictions_BODY  rule is explicitly set to  COUNT  (not  BLOCK ) across all environments. [ ] WAF stacks exist and are actively applied in  dev ,  qa ,  preprod , and  prd . [ ] AIAP CV uploads to the  /inference  endpoint return a 200 success response.
