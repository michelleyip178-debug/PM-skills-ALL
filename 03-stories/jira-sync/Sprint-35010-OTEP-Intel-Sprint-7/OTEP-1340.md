## Description

evaluated on :     Replace  pypdf  with  PyMuPDF  ( pymupdf ) for PDF text extraction in the  raw_overlap  pipeline path, add a post-chunking merge step (threshold=20 tokens) to consolidate tiny fragments, and remove the now-dead  _normalize_mega_lines  workaround. This fixes garbled text extraction on Canva-style multi-column PDF CVs and improves section detection, while maintaining identical chunk counts and competency quality. Problem pypdf produces garbled text on Canva-style multi-column PDFs (5 out of 14 test PDFs affected): Characters extracted with spaces between every letter: "D a n i e l M o r t o n" instead of "Daniel Morton" Multi-column layouts read left-to-right across columns instead of top-to-bottom within each column, causing headings to cluster together with no content between them Section headings like "W O R K E X P E R I E N C E" don't match the heading regex patterns, so the chunker can't detect EDUCATION/CERTIFICATIONS sections Critical failure:  Malay.pdf returns 0 competencies because the entire garbled text becomes 1 unchunkable blob The  _normalize_mega_lines  workaround was a band-aid that re-split long lines but couldn't fix the underlying garbling Solution Replace pypdf with PyMuPDF  in  cie/cv/extraction/pdf.py Use  page.get_text("text", sort=True)  for correct reading order on multi-column layouts PyMuPDF never produces garbled text on any tested PDF 3x faster extraction (14.8ms vs 44.3ms mean) Add merge step  in  cie/cv/raw_chunk.py PyMuPDF's cleaner extraction produces more granular chunks (individual cert lines, short bullets become their own chunks) _merge_small_chunks(chunks, min_merge_tokens=20)  consolidates adjacent same-section chunks below 20 tokens using pipe separator (" | ") Capped at MAX_CHUNK_TOKENS=100 per merged chunk threshold=20 empirically matches the original pypdf chunk count within 2% Evidence (data-driven, tested on 43 CVs: 14 PDF + 29 DOCX) Chunk count comparison (14 PDFs) Strategy Total chunks vs Original Original
