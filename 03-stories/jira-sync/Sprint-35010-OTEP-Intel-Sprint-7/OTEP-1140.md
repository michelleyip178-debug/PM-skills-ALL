## Description

Gap analysis (2026-08-05) of the  cie-backend / config-repo / intelligence-iac  pipelines, benchmarked against the OTEP reference system (CICD_WORKFLOW_GUIDE.md), found: Zero security scanning  on the two app/deploy repos (no SAST, secret detection, dependency scan, container scan; only intelligence-iac has SAST-IaC) No coverage measurement or SonarQube  (bare  pytest -q ) No prd path for applications  — the prd  gitlab-cie-deployer  role exists in iac but config-repo has no  apps/*/prd/  or  deploy:prd ; the promotion chain ends at preprd Fire-and-forget deploys  — no  services-stable  wait / stability poll, no rollback tooling; champion promotion and promotion MRs fire even if the rollout crash-loops No drift detection , despite the 2026-07-10 incident where an IaC apply silently reverted a console-set task-def env var and changed the served variant Inverted approval gradient  — preprd promotion is self-serve while qa is gated; iac  apply:prd  has no required approvers Mutable-tag hazards  — branch builds clobber  :latest ; cie-ingest task defs pin  :latest  (promotions produce no diff); worker/backend images already skewed in qa Strengths to preserve:  keyless OIDC AWS auth everywhere, the OTEP-624/700 eval regression gate, MR-reviewed GitOps promotion via config-repo, tightly-scoped per-purpose deploy roles. Missing credentials to provision:   SONAR_TOKEN  +  SONAR_PROJECTKEY  (masked, cie-backend) after SHIP-HATS SonarQube onboarding; optional  SLACK_WEBHOOK_URL  for notifications. Nothing needed for Keycloak (it is the OTEP platform's IdP, not a CIE CI concern). Never introduce static AWS keys. Breakdown: 9 stories under this epic (security baseline, SonarQube+coverage, deploy verification, prd wiring, promotion governance, drift detection, config-repo MR validation, artifact hygiene, observability/docs).
