## Description

User Story As  a consuming service from MCP Client,  I want  to submit a structured Job Description and receive a list of inferred, scored WOG competencies,  so that  I can automatically match job roles against the competency bank without having to re-implement the AI inference pipeline. Context & Background Currently, the CIE inference pipeline only supports extracting competencies from Resumes/CVs. Downstream consumers now require the ability to infer competencies from Job Descriptions (JDs). Because our ranking tail (embed -> retrieve -> rerank -> aggregate) is already input-agnostic, we do not need to build a new AI pipeline. We only need to build the JD-specific upstream parser (converting Careers@Gov JD JSON into text chunks) and expose it via the two required communication paths: HTTPS ( /jd-inference-json ) : Synchronous path over Transit Gateway for the MCP/Desk agents. Scope & Constraints In Scope:  Structured JSON input only (mapped to Careers@Gov CSV columns). Out of Scope:  File uploads (PDF/DOCX) for JDs are stubbed and deferred to a future iteration. Infrastructure:  No new ECS services or ECR repos are required. This will be deployed as new endpoints/handlers on the existing inference service. Reference Payload Dictionary The inference endpoints will expect payloads matching the Careers@Gov data structure: {
  "id_jd": "17899375",
  "jd": {
    "title": "Manager/Senior Manager, Research, Data Analytics and Insights (ICPD)",
    "ministry": "Non-HRPS Agencies",
    "functional_area": "Data Analytics",
    "hierarchy_level": "Manager",
    "what_the_role_is": "You will support SWDA's evidence-based planning...",
    "what_you_will_be_working": "As a Manager in Research, Data Analytics and Insights...",
    "what_we_are_looking_for": "You should have the following work experience..."
  },
  "n": 12
}
 High-Level Acceptance Criteria AC 1:  The  POST /jd-inference-json  endpoint successfully accepts JD JSON and returns a standard  InferResponse  with scored WOG competencies. AC 2:  The existing CV inference pipeline (both HTTP and SQS) continues to function with zero regressions (backwards compatibility maintained). AC 3:  The generic  reranker_v2.txt  prompt is updated to handle both CVs and JDs, and a new  variant_id  baseline is established. AC 4:  Integration and E2E tests for the JD paths are passing in the CI pipeline.  Example Input:  A single Careers@Gov JD row (dict) {
    "title": "Senior Policy Analyst",
    "ministry": "MOF",
    "agency": "Fiscal Policy Office",
    "functional_area": "Policy",
    "hierarchy_level": "Senior Officer",
    "what_the_role_is": "Lead fiscal policy reviews for government expenditure.",
    "what_you_will_be_working": "- Conduct cost-benefit analysis of subsidy programmes\n- Draft Cabinet papers; present findings to senior leadership\n- Coordinate with partner agencies on cross-cutting initiatives",
    "what_we_are_looking_for": "Strong analytical skills with 5+ years in public policy. Experience with econometric modelling preferred.",
    "other": ""
}
 Step 1 -  parse_jd  builds 3 sections (skips  other  because it's empty): Section header body ROLE DESCRIPTION Lead fiscal policy reviews for government expenditure. WORK SCOPE Conduct cost-benefit analysis of subsidy programmes\n- Draft Cabinet papers; present findings to senior leadership\n- Coordinate with partner agencies on cross-cutting initiatives REQUIREMENTS Strong analytical skills with 5+ years in public policy. Experience with econometric modelling preferred. Step 2 -  chunk_jd  runs  chunks_from_section  on each. The splitter ( _iter_units ) does: Split body on  \n  into lines Split each line on inline bullets ( _INLINE_BULLET_RE ) Strip bullet markers ( - * +  etc.) Split on statement boundaries ( ;  clauses via  _STATEMENT_SPLIT_RE ) Prefix with context ( section.header ) For the WORK SCOPE section, that produces chunks like: # chunk text 0 ROLE DESCRIPTION: Lead fiscal policy reviews for government expenditure. 1 WORK SCOPE: Conduct cost-benefit analysis of subsidy programmes 2 WORK SCOPE: Draft Cabinet papers 3 WORK SCOPE: present findings to senior leadership 4 WORK SCOPE: Coordinate with partner agencies on cross-cutting initiatives 5 REQUIREMENTS: Strong analytical skills with 5+ years in public policy. 6 REQUIREMENTS: Experience with econometric modelling preferred.
