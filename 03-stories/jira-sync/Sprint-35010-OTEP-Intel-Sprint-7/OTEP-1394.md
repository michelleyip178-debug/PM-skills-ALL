## Description

Request an ACM certificate for  *.dev.hrhub.gov.sg  in  ap-southeast-1  (intel-dev account 722448937858) via Terragrunt IaC.\n\n Spec: \n- Domain:  *.dev.hrhub.gov.sg  (wildcard covers  cie-intelligence.dev.hrhub.gov.sg  and future subdomains)\n- Key algorithm:  EC_prime256v1  (ECDSA P-256)\n- Validation method: DNS\n- Region:  ap-southeast-1 \n\n What to do: \n1. Add a new Terragrunt stack (e.g.  live/dev/dns/acm-cert/terragrunt.hcl ) that creates  aws_acm_certificate  and  aws_acm_certificate_validation \n2. Use the public zone from the R53 ticket to automatically create the CNAME validation record via  aws_route53_record \n3. Output  certificate_arn  so the ALB stack (OTEP-1127) can reference it as the HTTPS listener's certificate\n\n Why ECDSA:  Smaller key size, better performance, and aligns with modern TLS best practices over RSA-2048 (which was used in the 3 previously failed cert attempts for  cie-inference.dev.intelligence.gov.sg ).\n\n Blocked by:  Public R53 zone ticket (zone must exist and NS delegation must be active before DNS validation can complete).\n Blocks:  OTEP-1127 (HTTPS listener needs cert ARN).
