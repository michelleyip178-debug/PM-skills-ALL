## Description

Context The previous approach assumed AIAP AgentCore traffic would reach the CIE internal ALB via the GEN Transit Gateway. This assumption was incorrect — the GEN TGW is only for WOG intranet connectivity (COMET/GSIB), not inter-VPC application traffic. Inter-VPC app connectivity between AIAP and CIE requires VPC PrivateLink. What needs to be done Expose  cie-internal-alb  as a VPC Endpoint Service via the NLB → ALB pattern so AIAP can connect from their VPC using an interface VPC endpoint. Implementation (dev environment, account 722448937858) Create  module/nlb-privatelink/  — new Terraform module provisioning: Internal NLB (type  network ) in the same  private_edge  subnets as the ALB NLB target group (type  alb ) registering the existing ALB ARN NLB TCP listener on port 443 (pass-through — ALB handles TLS termination) VPC Endpoint Service backed by the NLB with  acceptance_required = true aws_vpc_endpoint_service_allowed_principal  for the AIAP account ARN Create  live/dev/edge/nlb-privatelink/terragrunt.hcl  — wire the module with VPC ID, subnet IDs, and ALB ARN from existing dependencies Update  live/dev/edge/internal-alb/terragrunt.hcl  — replace AIAP direct CIDRs ( 10.80.145.224/28 ,  10.80.145.240/28 ) in  ingress_cidrs  with the NLB subnet CIDRs ( 10.188.182.96/28 ,  10.188.182.112/28 ). PrivateLink traffic arrives from NLB ENIs in those subnets. Delete  live/dev/edge/alb-dns-alias/  — public DNS alias record pointing to an internal ALB serves no purpose. Intranet DNS is handled by GCC DNS (R53 Resolver profile). Post-deploy : Share the  endpoint_service_name  output with the AIAP team. AIAP creates an interface VPC endpoint in their VPC, we accept the connection. Key design decisions TCP listener (not TLS) : ALB already terminates TLS — double encryption is unnecessary acceptance_required = true : Endpoint connections must be explicitly accepted allowed_principal_arns  is a prerequisite: AWS blocks cross-account  CreateVpcEndpoint  calls when no principals are listed. AIAP account ID must be configured before they can connect. Same subnets as ALB : NLB in  private_edge  subnets keeps routing simple Prerequisites Confirm AIAP NPRD AWS account ID for  allowed_principal_arns Acceptance criteria module/nlb-privatelink/  created and passes  terraform validate live/dev/edge/nlb-privatelink/  created and passes  terragrunt validate  +  plan NLB target group health check passes (ALB is healthy target) VPC Endpoint Service is  available  with AIAP account as allowed principal ALB SG updated to allow NLB subnet CIDRs instead of AIAP direct CIDRs live/dev/edge/alb-dns-alias/  deleted AIAP team can create interface endpoint and reach  cie-internal-alb  on TCP/443 Implementation plan See:  docs/initiatives/cie-alb-https-connectivity/plans/nlb-privatelink-dev.md Related Corrects wrong TGW assumption from OTEP-1127/1393/1394/1395 OTEP-1426 (future: WAF IP set whitelisting)
