## Description

Context  We are wiring up the competency-review BYOMCP repo (AgentCore runtime) to call the CIE backend /inference endpoint so AI agents can assess CVs via MCP.   AIAP confirmed (2026-08-04): the BYOMCP MCP is already connected to the AgentCore  gateway and already has outbound connectivity to GEN. We do NOT need to touch TGW  routing on the AIAP side. What we need is: An entry point on our side so traffic from AIAP can reach CIE (internal ALB) SG/NACL rules whitelisting AIAP source CIDRs The MCP tool code itself API key plumbed end-to-end    Key   findings   from   current state of repositories: TGW attachments already exist per environment in intelligence-iac (externally owned, referenced) internal-alb module is fully coded in intelligence-iac/module/internal-alb/ but the  live/dev/edge/internal-alb/terragrunt.hcl.disabled file was disabled 2026-06-19 and  never provisioned (empty Terraform state). Inputs in it are wrong: target_port=3000  (frontend) and private_edge subnet (doesn't exist) - must be fixed before enabling. CIE runs on ECS Fargate on port 8080 in app_private subnets The internal_alb subnet tier exists: dev 10.188.182.96/28+10.188.182.112/28,  prd 10.80.197.224/28+10.80.197.240/28 ECS service SG has no ingress today (no ALB connected). The module wires it via  alb_security_group_id - needs to be passed.  (NOT NEEDED) INFERENCE_API_KEY is unset everywhere (fail-open in dev). Must be set for prod. API key for the MCP side: CI/CD masked var → TF_VAR_mcp_env_vars → AgentCore env →  MCP Python code → X-API-Key header to CIE. This is secure on the intranet.    User   Story:   Expose   CIE   inference   via   MCP   tool   As   a  GovTech   AI   product   using   the   AIAP   AgentCore   gateway ,  I   want  an MCP tool infer_competencies that accepts a CV file and returns competency scores,  so   that  AI agents e.g. Desk can call CIE without re-implementing the inference pipeline.
