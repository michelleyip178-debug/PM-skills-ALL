# OTEP-1323: Centralise S3 Server Access Logging — Replace sst-s3-psd-otep-{env}-tfstate-logs with dedicated s3-access-logs bucket using partitioned prefix

**Type:** Task
**Status:** Backlog
**Assignee:** boonsiangteh
**Story Points:** N/A

---

## Description

Context All S3 buckets in the OTEP IaC currently direct their server access logs to  sst-s3-psd-otep-{env}-tfstate-logs . This bucket name is misleading — it was originally created for Terraform state-related logging but has become a general S3 access log sink across all environments. Additionally, the  module/compute/s3  previously used a custom  log/${local.bucket_name}/  prefix as a workaround to separate logs per source bucket. Problem Misleading bucket name  —  tfstate-logs  implies the bucket holds Terraform state or state-related logs, causing confusion. Prefix workaround  — The  log/${local.bucket_name}/  prefix was a manual workaround. AWS now provides native partitioned prefix format ( [SourceAccountId]/[SourceRegion]/[SourceBucket]/[YYYY]/[MM]/[DD]/... ) which organises logs automatically and is Athena-optimised. No central logs bucket  — There is no dedicated, clearly-named bucket for S3 server access logs. Proposed Change Create a new dedicated S3 access logging bucket  sst-s3-psd-otep-{env}-s3-access-logs  in each environment via a new  live/{env}/compute/s3-access-logs/terragrunt.hcl  stack. This bucket has  enable_access_logging = false  (no self-logging loop). Update  module/compute/s3   aws_s3_bucket_logging  resource to use  target_object_key_format { partitioned_prefix { partition_date_source = "DeliveryTime" } }  with  target_prefix = "" . Retarget all existing  logging_target_bucket  references from  {env}-tfstate-logs  to  {env}-s3-access-logs  across all environments. The existing  tfstate-logs  bucket is retained (not deleted) — existing logs remain accessible; it simply stops receiving new logs. Scope module/compute/s3/main.tf  —  target_object_key_format  already added in  cloud-va-infra-gaps  branch New stacks:  live/{dev,qa,uat,prd}/compute/s3-access-logs/terragrunt.hcl Updated stacks: all live stacks with  logging_target_bucket Acceptance Criteria [ ]  sst-s3-psd-otep-{env}-s3-access-logs  exists in all four environments [ ] All S3 buckets using the module direct server access logs to the new bucket [ ] Log objects appear under  {account-id}/ap-southeast-1/{source-bucket}/  partitioned paths [ ]  tfstate-logs  bucket no longer receives new access log entries [ ] An ADR is created in OTEP Confluence documenting the centralised logging pattern
