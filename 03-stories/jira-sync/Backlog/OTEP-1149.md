## Description

Deploys are observationally silent: no  environment:  on cie-backend deploy jobs (no GitLab deployment history / DORA for the env that deploys every merge), zero notifications in any repo, and config-repo's README is GitLab boilerplate pointing at a nonexistent doc — a failed post-merge deploy on main fails silently where nobody is watching. Tasks cie-backend:  environment: {name: dev}  (+ worker/feedback variants) on deploy jobs — unlocks deployment history + DORA Notifications on deploy failure (minimum) for cie-backend deploys + config-repo deploy:qa/preprd + drift hits: provision  SLACK_WEBHOOK_URL  (or Teams) as a masked variable; adopt the non-fatal notifier contract (must never fail the calling job —  || true , unconditional exit 0) Rewrite config-repo README: actual promotion model, approval matrix, job-token allow-list + "Pipelines must succeed" prerequisites, rollback procedure (consolidate from existing cie-backend comments) cie-backend runbook: migrate-evalstore ordering, EVAL_GATE_OVERRIDE procedure (link eval/README), replay/judge operation Optional: GitLab Release per main deploy (release-cli, reuse the promotion changelog); prune stale  promote/*  branches (delete source branch on close) Acceptance criteria:  Failed main-branch deploy pings the channel; DORA dashboard populated for dev; a new joiner can promote + roll back from docs alone.
