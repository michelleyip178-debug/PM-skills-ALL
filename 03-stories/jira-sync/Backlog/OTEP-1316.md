# OTEP-1316: [PERF] Optimize role search: Push text matching and pagination into PostgreSQL queries (eliminate unbounded in-memory candidate loading)

**Type:** Task
**Status:** Backlog
**Assignee:** Pow Hwee TAN (PSD)

## Description

Related UAT / Defect Tickets OTEP-1287: Explore New roles - No search results for certain keywords (Candidate loading & search performance) Performance & Scalability Issue In role_search_repository.go (L99-113), text filtering, ranking, and pagination are intentionally omitted from the SQL layer and performed entirely in Go memory across all candidate rows. Technical Risk On every search query, PostgreSQL executes an unbounded UNION ALL query pulling all active roles and competency JSON blobs into application memory. The Go service then fetches all competency bank items, performs in-memory string prefix/contains matching, calculates match percentages, and sorts the slice in memory. As the WOG role catalogue scales across all public service agencies, this O(N) unpaginated database scan will cause severe memory ballooning, high I/O latency, and potential service degradation. Proposed Optimization Push text matching (ILIKE or pg_trgm trigram similarity index) directly into PostgreSQL search queries. Implement database-level pagination (LIMIT / OFFSET) to bound query result sets. Cache competency bank definitions to avoid repetitive DB lookups during search ranking.
