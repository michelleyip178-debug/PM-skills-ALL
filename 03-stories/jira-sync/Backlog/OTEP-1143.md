## Description

All deploys end at  aws ecs update-service  fire-and-forget (cie-backend  .gitlab-ci.yml:271-329 , config-repo  scripts/deploy.sh:69-76 ). A crash-looping rollout stays green, and champion promotion + promotion MRs fire anyway. No rollback tooling exists. Tasks Add rollout verification to cie-backend  .deploy-base  and config-repo  deploy.sh  — use the reference stability-poll shape: poll  rolloutState==COMPLETED  AND exactly one active deployment, fast-fail on  FAILED  printing recent service events, configurable timeout (not the bare 10-min default waiter) Failing rollout must block  promote-champion  and  open-promotion-mrs  (they  needs: deploy-inference ) [IAC]  iac handoff: enable ECS deployment circuit breaker with  rollback=true  on cie-inference/worker/feedback services Write rollback runbook: re-run deploy at previous sha (dev); revert promotion MR (qa/preprd) Consider: pre-migration RDS snapshot step in migrate-evalstore (fails-closed, deterministic snapshot id) Acceptance criteria:  A deliberately-broken image (bad healthcheck) turns the deploy job red and no promotion MR opens.
