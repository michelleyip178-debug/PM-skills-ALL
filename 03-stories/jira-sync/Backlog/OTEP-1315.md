# OTEP-1315: [CORE] Role Search: Align autocomplete and search contract to prevent silent dropping of roles with 0 functional competencies

**Type:** Bug
**Status:** Backlog
**Assignee:** Pow Hwee TAN (PSD)
**Story Points:** N/A

---

## Description

Related UAT / Defect Tickets OTEP-1287: Explore New roles - No search results for certain keywords Problem Description In Explore New Roles, typing keywords such as 'Counter services' or 'Sewerage Information' displays matching role suggestions in the autocomplete dropdown. However, submitting the search returns 0 results and displays 'No roles found' (OTEP-1287). Root Cause Diagnosis CatalogueRepository.ListRoleCatalogue (Autocomplete) checks only whether the title exists in SQL (ILIKE '%query%'). It finds the role and presents it to the user. RoleSearchService.SearchRoles checks candidate functional competencies in Go memory (role_search_service.go:L88-L91). If a role has 0 functional competencies mapped (HasFunctional == false), it is silently dropped from the search results. This creates a direct contract disconnect between autocomplete suggestions and search execution, degrading user trust. Proposed Fix Option A: Update SearchRoles to allow roles with 0 functional competencies to be returned with a 0% match percentage instead of silently discarding them. Option B: Align CatalogueRepository.ListRoleCatalogue to filter suggestions to only include roles with valid competency mappings. Ensure database seeding guarantees all active catalogue roles have valid functional competency associations.
