# OTEP-1317: [CORE] Frontend State: Scope useReportedIssue localStorage keys by profileId to prevent cross-session state leakage

**Type:** Bug
**Status:** Backlog
**Assignee:** Adrian Lo
**Story Points:** N/A

---

## Description

Related UAT / Defect Tickets OTEP-1260: [EDGE] EDGE-07 - Report issue (missing role-based competencies): toast, button greys to 'issue reported', synced across pages (OTEP-512) Bug Description In Your Development, the 'Report issue' button state leaks across user accounts and browser sessions on the same machine (OTEP-1260). When a new officer logs in, the button may already be disabled and show 'Issue Reported' before any action is taken. Root Cause Diagnosis In otep-web/src/hooks/useReportedIssue.ts (L9-L13), reported status is stored globally in window.localStorage using a static key prefix without user profile scoping: 'yourdevelopment-reported-issue:missing_role_competencies'. When one user clicks 'Report issue', the flag is persisted globally in the browser. Any other user logging in on the same browser inherits the 'true' state. Proposed Fix Scope the localStorage key by the authenticated officer's profile ID: 'yourdevelopment-reported-issue:${profileId}:${issueType}'. Alternatively, query the backend reporting endpoint/session state to determine whether the authenticated officer has previously reported the issue.
