## Description

config-repo has no MR pipeline at all; a malformed task-definition.json or a nonexistent image tag is only discovered when the post-merge deploy fails on main (which the  HEAD~1..HEAD  diff detection then never retries — env git state ends up ahead of reality). Tasks Add MR-pipeline  validate  job ( merge_request_event ,  changes: apps/** ) jq empty  every changed task-definition.json; assert required fields (family, cpu/memory) Assert image tag !=  latest  for service families (grandfather cie-ingest until the artifact-hygiene story lands) skopeo inspect  the source GitLab-registry image:tag exists pre-merge (CI_JOB_TOKEN, existing allow-list) shellcheck  scripts/ Make deploy.sh failure-re-runnable (compare desired vs live revision, not just the commit diff) Acceptance criteria:  An MR with malformed JSON or a typo'd tag goes red before merge.
