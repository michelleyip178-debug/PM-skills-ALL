## Description

Analytics Instrumentation – Explore New Roles User Story As a product manager and analyst, I want to track how officers search, filter, and compare roles in Explore New Roles so that I can measure role discovery behaviour, identify search and filter friction, and understand whether officers engage with competency gap comparisons.  Background / Context The Explore New Roles experience allows officers to discover role profiles across agencies, job families, and job functions. This section allows officers to: Search for role profiles by keyword Filter roles by Job Family, Job Function, and Agency View matching role profiles Select a role from the search results Compare competencies they already have against competencies they need to develop Expand competency descriptions Expand all competency descriptions Clear search and filters Return to the My Development page Analytics from this section will be used to validate whether officers actively explore career options, whether search and filters help them discover relevant roles, and whether competency comparison supports career development decision-making.  Scope In Scope Instrumentation of Explore New Roles interactions including: Explore New Roles page view Search submitted Filter applied Search results returned No-results returned Clear search Role selected from search results Individual competency description expansion Show All competency descriptions Back navigation to My Development Out of Scope My Development profile details instrumentation "Based on your current role" instrumentation Course recommendation instrumentation Save Target Role instrumentation Profile page competency editing instrumentation User identity and person properties (covered in OTEP-488) Session replay  Events 1. explore_new_roles_page_viewed Triggered when the Explore New Roles page successfully loads. Properties Property Type page_state String Accepted values: default_empty_state results_loaded no_results Purpose Measure adoption of the Explore New Roles page and understand whether officers land on the default empty state, a populated results state, or a no-results state.  2. role_search_submitted Triggered when an officer clicks the  Search  button after entering a keyword and/or applying filters Properties Property Type search_term String search_term_length Number filter_job_family_count Number filter_job_function_count Number filter_agency_count Number search_mode String Accepted values for  search_mode : keyword_only filters_only keyword_and_filters Purpose Measure search intent and understand whether officers prefer keyword search, filters, or a combination of both. Filter values are intentionally not captured in this event. This event represents the search submission, while filter behaviour is captured separately in  role_filter_applied .  3. role_search_autocomplete_selected Triggered when an officer selects an autocomplete suggestion from the Explore New Roles search bar. Properties Property Type search_term String selected_value String Purpose Measure autocomplete adoption and understand whether officers rely on autocomplete suggestions instead of completing a free-text search. Supports analysis of: Autocomplete adoption rate Most frequently selected role suggestions Search behaviour when autocomplete is used versus when it is not  4. role_filter_applied Triggered when an officer applies or changes a filter selection. Properties Property Type filter_type String selected_count Number filter_values Array[String] Accepted values for  filter_type : job_family job_function agency Purpose Measure filter usage and understand which Job Families, Job Functions, and Agencies officers are most interested in exploring. Capturing the selected values allows Product to identify the most frequently explored career domains and agencies.  5. role_search_results_returned Triggered when search or filter results are returned and displayed. Properties Property Type results_count Number search_mode String filter_job_family_count Number filter_job_function_count Number filter_agency_count Number Accepted values for  search_mode : keyword_only filters_only keyword_and_filters Purpose Measure search result quality, result volume, and search-to-role-selection conversion. The filter count properties indicate how many filters were applied when the result set was generated. This helps determine whether users obtain more useful result sets after applying filters.  6. role_search_no_results_returned Triggered when a submitted search or filter combination returns no matching roles. Properties Property Type search_term String filter_job_family_count Number filter_job_function_count Number filter_agency_count Number Purpose Measure failed discovery attempts and identify search or filter combinations that consistently return no results, informing future improvements to role profile coverage and search relevance.  7. role_search_load_more_results Triggered when additional role search results are loaded and displayed as the officer scrolls through the results list. Properties Property Type results_count Number load_batch_number Number Purpose Measure how deeply officers browse beyond the initial role results and understand overall engagement with the role search results. Capturing the number of additional result batches loaded enables analysis of: Average browsing depth Number of additional result batches viewed Approximate number of roles viewed beyond the initial results Engagement with role search results  8. role_search_cleared Triggered when an officer clicks  Clear Search  or clears all search and filter criteria. Properties Property Type had_keyword Boolean had_filters Boolean Purpose Measure whether officers restart their search journey, which may indicate poor search relevance, overly restrictive filters, or a desire to begin a new exploration.  9. explored_role_selected Triggered when an officer manually selects a role card from the search results list. This event should  not  be triggered for the default first role automatically selected after search results load. Properties Property Type role_rank Number job_id String role_name String match_percentage Number matched_competency_count Number missing_competency_count Number Purpose Measure which search results officers actively choose to inspect and understand whether role selection is influenced by ranking, competency match percentage, or competency gap size. results_count  is intentionally excluded because it is already captured in  role_search_results_returned .  10. explored_role_competency_accordion_expanded Triggered when an officer expands an individual competency description within the selected role comparison panel. Properties Property Type competency_status String Accepted values: you_have_this to_develop Purpose Measure whether officers inspect competency descriptions and whether they are more interested in competencies they already possess or competencies they need to develop.  11. explored_role_competencies_expand_all_clicked Triggered when an officer clicks  Show all  or  Expand all  to reveal all competency descriptions in the selected role comparison panel. No additional properties required. Purpose Measure intent to inspect all competency descriptions in the selected role comparison panel and understand whether officers want the full role comparison before deciding whether the role is relevant to them.  12. explore_new_roles_back_clicked Triggered when an officer clicks  Back  to return to the My Development page. No additional properties required. Purpose Measure navigation back to My Development and understand whether officers return after exploring roles.  Acceptance Criteria All events listed in this ticket are instrumented and captured in PostHog. Event names follow the approved analytics taxonomy. Event properties are sent using consistent naming conventions and data types. Events are emitted once per user action or once per relevant page or result state. Events fail gracefully and do not impact user experience if analytics services are unavailable. Event payloads are visible and queryable in PostHog. Event properties conform to the specifications defined in this ticket. explore_new_roles_page_viewed  is captured when the Explore New Roles page loads successfully. role_search_submitted  is captured whenever an officer executes a search after entering a keyword, applying one or more filters, or selecting an autocomplete suggestion. role_search_autocomplete_selected  is captured whenever an officer selects an autocomplete suggestion. role_filter_applied  is captured whenever a Job Family, Job Function, or Agency filter is applied or changed. role_filter_applied  includes the selected filter values. role_search_results_returned  is captured whenever search or filter results are returned and displayed. role_search_no_results_returned  is captured whenever a submitted search or filter combination returns no matching roles. role_search_load_more_results  is captured whenever additional role search results are loaded and displayed through scrolling. role_search_cleared  is captured whenever an officer clicks  Clear Search  or clears all search and filter criteria. explored_role_selected  is captured only when an officer manually selects a role from the search results. explored_role_selected  is not captured for the default role automatically selected after search results are loaded. explored_role_competency_accordion_expanded  is captured whenever an officer expands an individual competency description. explored_role_competencies_expand_all_clicked  is captured whenever an officer clicks  Show all  or  Expand all . explore_new_roles_back_clicked  is captured whenever an officer clicks  Back . Product teams are able to build dashboards and funnels for Explore New Roles page adoption, search behaviour, filter usage, search effectiveness, browsing depth, role exploration, competency engagement, and navigation back to My Development.  Success Metrics Supported This instrumentation enables measurement of: % of officers who view Explore New Roles % of officers who submit a search Autocomplete adoption rate % of officers who use filters Most-used Job Family, Job Function, and Agency filters Most frequently selected filter values Search mode distribution Average number of results returned No-results rate Average number of additional role result batches loaded per search Search-to-role-selection conversion rate Average number of roles explored per search result set Role selection rate by rank Role selection rate by competency match percentage % of officers who inspect competency descriptions % of officers who inspect competencies marked  "To develop" % of officers who use  Show all  /  Expand all Drop-off from page view to search submission Drop-off from search results to role selection  Definition of Done  All events listed in scope are implemented and visible in PostHog. Event names and properties match the specification. Event payloads are validated in PostHog. Default empty state, search submission, autocomplete, filtering, search results returned, no-results, load more results, clear search, role selection, competency expansion,  Show all  /  Expand all , and  Back  navigation flows are tested end-to-end. No direct PII is sent in event payloads. Product teams can build dashboards for role discovery, search quality, filter usage, browsing behaviour, role exploration, competency engagement, and navigation back to My Development without additional engineering work.
