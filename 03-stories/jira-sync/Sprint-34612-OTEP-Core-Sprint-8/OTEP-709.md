## Description

User Story As a Product Manager and analyst, I want to track how officers interact with the Course Discovery Page so that I can measure search effectiveness, filter usage, browsing depth, and how officers move from discovery into course evaluation.  Background / Context The Course Discovery Page is the main catalogue experience for officers who want to browse and search available courses. Officers can: Search for courses Use autocomplete suggestions Apply filters Browse paginated results Click a course tile to view its detail page See a  Recommended for you  swimlane on the page Recommendation generation, impression, page change, and recommendation click instrumentation for the  Recommended for you  swimlane are tracked separately under  Analytics – Course Recommendations .  This ticket captures Course Discovery Page-specific interactions that are not covered by that shared recommendation instrumentation. To support funnel analysis, the page view event will also capture  how the officer arrived on the Course Discovery Page , including the case where they were automatically routed here because no recommendations were available on the Course Landing Page.  Scope In Scope Instrumentation of: Course Discovery Page views Navigation source into the Course Discovery Page Course search Search autocomplete selection Course filters Clear filters Search result pagination Course tile clicks from search results Out of Scope Course recommendation instrumentation (covered under  Analytics – Course Recommendations ) Course Landing Page instrumentation Course Detail Page instrumentation LEARN platform analytics User identity and person properties Session replay  Events 1. course_discovery_page_viewed Triggered when the Course Discovery Page loads. Properties Property Type source_page String source_section String Accepted values for  source_page my_development_page course_landing_page Accepted values for  source_section When  source_page = my_development_page based_on_current_role explore_new_roles When  source_page = course_landing_page explore_all_courses_cta no_recommendations_redirect Purpose Measure how officers arrive at the Course Discovery Page and distinguish between officers intentionally exploring courses versus officers automatically redirected because no recommendations were available. Supports analysis of: Discovery Page traffic by originating page Discovery Page traffic by originating section Users redirected because no recommendations were available Users exploring courses from different sections in My Development Users exploring the wider course catalogue from the Course Landing Page  2. course_search_submitted Triggered when a search is executed after an officer enters a keyword or applies one or more filters. Properties Property Type search_term String search_term_length Number filter_class_type_count Number filter_domain_count Number filter_provider_count Number search_mode String Accepted values for  search_mode keyword_only filters_only keyword_and_filters Purpose Measure search intent and understand whether officers prefer keyword search, filters, or a combination of both. Filter values are intentionally not captured in this event. This event represents the search submission, while filter behaviour is captured separately in  course_filter_applied .  3. course_search_autocomplete_selected Triggered when an officer selects an autocomplete suggestion. Properties Property Type search_term String selected_value String autocomplete_category String Accepted values for  autocomplete_category course domain Purpose Measure autocomplete adoption and understand whether officers rely on autocomplete suggestions instead of completing a free-text search.  4. course_filter_applied Triggered when an officer applies or changes a filter selection. Properties Property Type filter_type String selected_count Number filter_values Array[String] Accepted values for  filter_type class_type domain provided_by Purpose Measure filter usage and understand which Class Types, Domains, and Providers officers are most interested in exploring. Capturing the selected values allows Product to identify the most frequently explored learning domains, providers, and delivery formats.  5. course_search_results_returned Triggered when search or filter results are returned and displayed. Properties Property Type results_count Number search_mode String filter_class_type_count Number filter_domain_count Number filter_provider_count Number Accepted values for  search_mode : keyword_only filters_only keyword_and_filters Purpose Measure search and filter effectiveness, including how many results are returned for a given search or filter combination, and whether officers are finding relevant courses.  6. course_search_no_results_returned Triggered when a submitted search or filter combination returns no matching courses. Properties Property Type search_term String filter_class_type_count Number filter_domain_count Number filter_provider_count Number Purpose Measure failed course discovery attempts and identify search terms or filter combinations that consistently return no results, informing future improvements to course catalogue coverage, search relevance, and filtering experience.  7. course_search_page_changed Triggered whenever an officer navigates to another page of search results. Properties Property Type page_number Number Purpose Measure browsing depth and understand how far officers explore beyond the first page of search results. Together with  course_search_submitted , this event enables analysis of: Average number of search result pages viewed Search browsing depth Search engagement Discovery behaviour  8. course_search_cleared Triggered when an officer clicks  Clear Search  or clears all search and filter criteria. Properties Property Type had_keyword Boolean had_filters Boolean Purpose Measure whether officers restart their course discovery journey, which may indicate poor search relevance, overly restrictive filters, or a desire to begin a new course exploration.  9. course_tile_clicked Triggered when an officer clicks a course tile from the search results. Note:  Recommended course tile clicks from the  Recommended for you  swimlane continue to be instrumented under  Analytics – Course Recommendations  and are intentionally excluded from this event. Properties Property Type course_id String course_name String course_rank Number Purpose Measure click-through rate from search results and understand whether officers are selecting relevant courses from the catalogue. Capturing ranking enables analysis of: Search result click-through rate Click-through rate by course Click-through rate by search result ranking Search relevance  Acceptance Criteria All events listed in this ticket are instrumented and captured in PostHog. Recommendation instrumentation for the  Recommended for you  swimlane continues to be captured under  Analytics – My Dev Course Swimlanes . Event names follow the approved analytics taxonomy. Event properties are sent using consistent naming conventions and data types. Events are emitted once per user action or once per relevant page load. Events fail gracefully and do not impact user experience if analytics services are unavailable. Event payloads are visible and queryable in PostHog. Event properties conform to the specifications defined in this ticket. course_discovery_page_viewed  is captured whenever the Course Discovery Page loads. course_discovery_page_viewed  captures the correct  source_page  and  source_section  for officers arriving from: My Development → Based on your current role. My Development → Explore New Roles. Course Landing Page → Explore all courses CTA. Course Landing Page → Automatic redirect due to no recommendations. course_search_submitted  is captured whenever a search is executed after an officer enters a keyword or applies one or more filters. course_search_autocomplete_selected  is captured whenever an officer selects an autocomplete suggestion. course_filter_applied  is captured whenever an officer applies or changes a filter selection. course_search_results_returned  is captured whenever search or filter results are returned and displayed. course_search_no_results_returned  is captured whenever a submitted search or filter combination returns no matching courses. course_search_page_changed  is captured whenever an officer navigates between pages of search results. course_search_cleared  is captured whenever an officer clicks  Clear Search  or clears all search and filter criteria. course_tile_clicked  is captured whenever an officer clicks a course tile from the search results. Product teams are able to build dashboards and funnels for Discovery Page traffic sources, search behaviour, filter usage, search effectiveness, browsing depth, and search result engagement.  Success Metrics Supported This instrumentation enables measurement of: Discovery Page traffic by originating page Discovery Page traffic by originating section % of officers entering from My Development % of officers entering from the Course Landing Page % of officers redirected due to no recommendations Most common search terms Search adoption rate Search mode distribution Autocomplete adoption rate Most frequently used filters Most frequently selected filter values Average number of search result pages viewed Search result click-through rate Search result click-through rate by course Search result click-through rate by ranking Funnel from Discovery Page entry → Search → Search Results → Course Detail  Definition of Done All events listed in scope are implemented and visible in PostHog. Recommendation instrumentation under  Analytics – Course Recommendations  continues to function as specified. Event names and properties match the specification. Event payloads are validated in PostHog. Course Discovery Page view, search submission, autocomplete, filtering, search results returned, no results returned, clear search, pagination, and course tile click flows are tested end-to-end. No direct PII is sent in event payloads. Product teams can build dashboards for Discovery Page traffic sources, search performance, filter usage, browsing behaviour, search effectiveness, and course engagement without additional engineering work.
