## Description

Analytics Instrumentation – Based on Your Current Role User Story As a product manager and analyst, I want to track how officers interact with the “Based on your current role” section so that I can measure whether officers engage with recommended roles and inspect competency gaps.  Background / Context The “Based on your current role” section recommends roles based on the officer’s current role, grade, and competency profile. This section allows officers to: View recommended roles based on their current role See competency match percentages for recommended roles Select a recommended role Compare competencies they already have against competencies they need to develop Expand competency rows to read descriptions Expand all competency descriptions Analytics from this section will be used to validate whether officers engage with recommended role options and whether competency gap information is useful enough for officers to inspect in detail.  Scope In Scope Instrumentation of “Based on your current role” interactions including: Section impression Recommended role selection Individual competency accordion expansion Expand All interaction Out of Scope Save target role instrumentation Recommended role card impression tracking Default selected role tracking as a user action Role comparison panel impression tracking as a separate event Collapse All interaction My Development profile details and edge case instrumentation Explore New Roles search and filter instrumentation Course recommendation impressions and clicks Course carousel navigation Profile page competency editing instrumentation User identity and person properties, covered in OTEP-488 Session replay  Events 1. based_on_current_role_section_viewed Triggered when the “Based on your current role” section is successfully displayed. Properties Property Type recommended_role_count Number Purpose Measure how many officers are shown the “Based on your current role” section and whether recommended roles are available. A  recommended_role_count  of  0  indicates that no recommendations were available for the officer.  2. recommended_role_selected Triggered when an officer manually selects a recommended role card from the left panel. This event should not be triggered for the default first role that is automatically selected on page load. Properties Property Type role_name String job_id Number role_rank Number match_percentage Number recommendation_type String matched_competency_count Number missing_competency_count Number Accepted values for  recommendation_type : lateral vertical Purpose Measure whether officers actively explore recommended roles beyond the default selection, and understand whether role selection behaviour is influenced by rank, competency match percentage, recommendation type, or competency gap size.  3. role_competency_accordion_expanded Triggered when an officer expands an individual competency row in the role comparison panel. Properties Property Type competency_status String Accepted values for  competency_status : you_have_this to_develop Purpose Measure whether officers inspect competency descriptions and whether they are more interested in competencies they already have or competencies they need to develop.  4. role_competencies_expand_all_clicked Triggered when an officer clicks “Expand all” in the competency comparison panel. Properties Property Type missing_competency_count Number matched_competency_count Number Purpose Measure intent to inspect the full competency comparison in detail and identify whether officers need broader context to understand the role gap.  Acceptance Criteria All events listed in this ticket are instrumented and captured in PostHog. Event names follow the above analytics taxonomy. Event properties are sent using consistent naming conventions and data types. Events are emitted once per user action or once per relevant section impression. Events fail gracefully and do not impact user experience if analytics services are unavailable. Event payloads are visible and queryable in PostHog. Event properties conform to the specifications defined in this ticket. based_on_current_role_section_viewed  is captured when the section is displayed. based_on_current_role_section_viewed  includes the correct  recommended_role_count . recommended_role_selected  is captured only when an officer manually selects a recommended role card. recommended_role_selected  is not captured for the default first role selected automatically on page load. role_competency_accordion_expanded  is captured when an officer expands an individual competency row. role_competencies_expand_all_clicked  is captured when an officer clicks “Expand all”. Product teams are able to build funnels and dashboards for: Recommended role section availability Recommended role selection rate Selection behaviour by role rank Selection behaviour by match percentage Selection behaviour by recommendation type Competency gap inspection Expand All usage  Success Metrics Supported This instrumentation enables measurement of: % officers who are shown the “Based on your current role” section % officers with recommended roles available % officers with no recommended roles available % officers who manually select a recommended role Recommended role selection rate by rank Recommended role selection rate by match percentage Recommended role selection rate by lateral vs vertical recommendation % officers who inspect competency descriptions % officers who inspect competencies marked “To develop” % officers who use Expand All Drop-off from recommended role exposure to competency gap inspection  Definition of Done All events listed in scope are implemented and visible in PostHog. Event names and properties match the specification. Event payloads are validated in PostHog. Recommended role section display, no-recommendation state, manual role switching, competency accordion expansion, and Expand All flows are tested end-to-end. No direct PII is sent in event payloads. Product team can build recommended role engagement and competency gap inspection dashboards without additional engineering work.
