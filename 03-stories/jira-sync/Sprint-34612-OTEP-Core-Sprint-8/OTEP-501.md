## Description

User Story As a product manager and analyst, I want to track how officers interact with the Profile and Competencies experience so that I can measure engagement, identify friction points, understand competency management behaviours, and validate whether officers actively curate their competency profile.  Background / Context The Profile page is the primary landing page after login and forms the foundation of the OTEP competency experience. This page allows officers to: View their profile information and role context View role-based competencies automatically associated with their role Hide or unhide role competencies from their profile Add self-declared competencies Remove self-declared competencies Discover competencies through keyword search (self-declared) Generate competency suggestions from CV upload/inference Analytics from this feature will be used to validate product hypotheses, monitor adoption, identify friction points, and support future optimisation decisions.  Scope In Scope Instrumentation of Profile and Competency-related user interactions including: Profile page views Role competency management Self-declared competency management Competency search Competency description views Save actions Abandonment of competency editing flows Issue reporting for missing competencies Out of Scope Names of competencies removed or added for self-declared competencies  Names of competencies added through inference Count of role-based competencies that are hidden and shown (only capture names) Names of self-declared competencies that are added and removed (only capture count) Name and count of competencies being selected or deselected while editing Which competency user clicks the “eye” icon for Login instrumentation User identity and trait identification (covered   ) Course recommendations analytics Opportunities analytics My Development analytics Session replay  Events 1. profile_page_viewed Triggered when the Profile page successfully loads. Properties Property Type role_competency_count Number additional_competency_count Number Purpose Measure profile page adoption and engagement, establish the baseline competency profile for each session, and support profile page funnel analysis.  2. role_competency_edit_opened Triggered when a user enters Role Competency edit mode. No additional properties required. Purpose Measure the percentage of officers who attempt to customise their role-based competency profile.  3. role_competency_changes_saved Triggered when role competency changes are successfully saved. Properties Property Type hidden_core_competencies Array[String] shown_core_competencies Array[String] hidden_functional_competencies Array[String] shown_functional_competencies Array[String] Purpose Identify competencies that are consistently hidden or restored by officers. This may indicate competencies that are outdated, poorly understood, incorrectly assigned, or no longer relevant to certain roles. Supports future review and refinement of competency frameworks. Note: competency counts are intentionally not captured; only the specific competency names changed in the session are tracked.  4. competency_filter_selected Triggered when a user switches between competency filters. Properties Property Type filter_type String Accepted values: all core functional Purpose Understand whether officers use competency categorisation to navigate their profile and assess whether the Core vs Functional competency distinction is useful and discoverable.  5. competency_add_started Triggered when a user initiates the Add Competency journey. Properties Property Type entry_point String Accepted values: plus_icon empty_state Purpose Measure intent to add competencies and identify drop-off between initiating and completing the competency addition journey.  6. competency_search_performed Triggered when a competency search is executed. Properties Property Type search_term String results_count Number Purpose Measure search behaviour, search quality, zero-result searches, and search-to-add conversion. Identify gaps in competency discoverability and opportunities to improve search relevance.  7. competency_description_eye_viewed Triggered when a user clicks the eye icon to view a competency description. No additional properties required. Purpose Measure how frequently officers inspect competency descriptions before taking action. High usage may indicate users require additional context to understand competencies or make competency management decisions.  8. competency_added Triggered when a competency is successfully added to the user's profile via the "Add to Profile" action. Properties Property Type source String Accepted values: keyword_search inference Purpose Measure competency profile growth and determine which competency acquisition methods are most effective in driving profile completion. This event will be used together with  competency_search_performed  and  competency_inference_accepted  to analyse conversion across competency acquisition journeys.  9. self_declared_competency_edit_opened Triggered when a user enters edit mode for self-declared competencies. No additional properties required. Purpose Measure engagement with self-declared competency management and identify how many officers actively maintain their competency profile.  10. self_declared_competencies_saved Triggered when self-declared competency changes are successfully saved. Properties Property Type added_count Number removed_count Number total_count_after Number Purpose Measure competency profile curation behaviour, profile growth over time, and the extent to which officers actively maintain and update their competency profile.  11. competency_edit_abandoned Triggered when a user enters a competency edit flow but exits without saving changes. Properties Property Type edit_type String Accepted values: role_competencies self_declared_competencies Purpose Identify friction points in competency management journeys and quantify where users begin editing but do not complete the action.  12. issue_reported Triggered when a user submits an issue report. Properties Property Type source_page String issue_type String Accepted values for source_page: profile my_development Examples of issue_type: missing_role_competencies (profile page) missing_role_grade (my dev page) other Purpose Monitor data quality issues, identify recurring profile inaccuracies, and support prioritisation of data remediation efforts.  13. competency_tooltip_viewed [added on 26 Jun] Triggered when a user clicks the information tooltip associated with a competency section. Properties Property Type tooltip_type String source_page String Accepted values for  tooltip_type : core functional Accepted values for  source_page : profile Purpose Measure how often officers require additional guidance to understand competency concepts. Compare tooltip usage across competency types and pages to identify where users require additional clarification or improvements to content and information architecture.   Acceptance Criteria All events listed in this ticket are instrumented and captured in PostHog. Event names follow the above analytics taxonomy. Event properties are sent using consistent naming conventions and data types. Events are emitted once per user action. Events fail gracefully and do not impact user experience if analytics services are unavailable. Event payloads are visible and queryable in PostHog. Event properties conform to the specifications defined in this ticket. Product teams are able to build funnels and dashboards for: Profile page adoption Competency edit completion Competency edit abandonment Search-to-add conversion Competency profile growth Competency filter usage Profile issue reporting  Success Metrics Supported This instrumentation enables measurement of: % officers who view Profile % officers who enter competency editing flows % officers who save competency changes % officers who add self-declared competencies Preferred competency acquisition path (keyword search vs inference) Search-to-add conversion rate Competency edit completion rate Competency edit abandonment rate Competency profile growth over time Competency filter usage Competency discovery behaviour Competencies frequently hidden by officers Profile quality issues reported Profile page engagement and drop-off  Definition of Done All events listed in scope are implemented and visible in PostHog. Event names and properties match the specification. Event payloads are validated in PostHog. User flows have been tested end-to-end. Product team can build adoption, engagement, competency management, competency discovery and inference-quality dashboards without additional engineering work.
