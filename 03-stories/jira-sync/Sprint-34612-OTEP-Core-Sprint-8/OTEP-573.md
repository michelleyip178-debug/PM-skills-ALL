## Description

Analytics Instrumentation – My Development Profile Details & Edge Cases User Story As a product manager and analyst, I want to track how officers interact with the My Development profile details section so that I can measure adoption, identify data quality issues, understand whether officers act on missing competency data, and validate whether officers proceed from profile awareness into career development actions.  Background / Context The My Development page helps officers understand their current role context, functional competencies, and development pathways. The profile details section allows officers to: View their current role and grade View functional competencies from their current role View self-declared competencies they have added Navigate to Profile to manage or add self-declared competencies Report issues when role, grade, or role-based competencies cannot be retrieved Navigate to Explore New Roles See the appropriate empty state when role, grade, or competency data is unavailable Analytics from this section will be used to validate whether officers engage with their competency profile, monitor data quality edge cases, and understand whether missing data prevents officers from progressing into role exploration.  Scope In Scope Instrumentation of My Development profile details and edge case interactions including: My Development page view Profile detail state shown Functional competency tooltip interaction Functional competency View More interaction Manage Competencies CTA Add Competencies CTA Explore New Roles CTA Issue reporting for missing role, grade, or role-based competencies Out of Scope User identity and person properties, covered in OTEP-488 Profile page competency editing instrumentation Recommended role card instrumentation Role comparison detail panel instrumentation Explore New Roles search and filter instrumentation Course recommendation instrumentation Course click-through and course attribution Session replay Separate empty state impression events View Less / collapse tracking Disabled issue report state tracking  Events 1. my_development_page_viewed Triggered when the My Development page successfully loads. Properties Property Type profile_state String role_retrieved Boolean grade_retrieved Boolean role_competencies_available Boolean self_declared_competencies_available Boolean recommended_roles_section_available Boolean Accepted values for  profile_state : complete_profile missing_self_declared_competencies missing_role_competencies missing_role_and_self_declared_competencies missing_role_grade_and_role_competencies missing_role_grade_and_all_competencies Purpose Measure My Development page adoption and quantify how many officers land in each profile data state. This supports monitoring of data quality, edge case prevalence, and whether missing profile data affects downstream engagement.  2. competency_tooltip_viewed (same event name as Profile Page) Triggered when the officer views the tooltip beside "Functional Competencies". Property Type tooltip_type String source_page String Accepted values for tooltip_type: functional Accepted values for source_page: my_development Purpose Measure how often officers require additional guidance to understand functional competencies on My Development. Compare tooltip usage across pages to identify where users require additional clarification or improvements to content and information architecture. Purpose Measure whether officers need additional explanation to understand functional competencies. High tooltip usage may indicate that the competency taxonomy or section copy requires clearer explanation.  3. functional_competencies_expanded Triggered when the officer clicks "View more" to expand a functional competency section beyond the default visible list. Properties Property Type competency_section String Accepted values: from_this_role self_declared Purpose Measure whether officers explore beyond the default competency preview and understand which competency sections generate deeper engagement.  4. manage_competencies_clicked Triggered when the officer clicks either "Manage competencies" or "Add competencies" from the My Development page. Properties Property Type entry_point String Accepted values for  entry_point : manage_competencies_button self_declared_competencies_empty_state Purpose Measure intent to update competency data from My Development and identify whether officers are navigating to Profile because they want to manage existing competencies or add missing self-declared competencies.  5. explore_new_roles_clicked Triggered when the officer clicks the "Explore new roles" CTA from the My Development page. No additional properties required. Purpose Measure whether officers proceed from understanding their current profile and competencies into active role exploration.  6. issue_reported Triggered when an officer submits an issue report from the My Development page. Properties Property Type source_page String issue_type String Accepted values for  source_page : my_development Accepted values for  issue_type : missing_role_competencies missing_role_grade Purpose Monitor data quality issues, identify recurring profile inaccuracies, and support prioritisation of data remediation efforts. Note: Officer identity, date, and time should be derived from PostHog person/session metadata where possible. Do not send NRIC, name, email, or direct PII.  Acceptance Criteria All events listed in this ticket are instrumented and captured in PostHog. Event names follow the above analytics taxonomy. Event properties are sent using consistent naming conventions and data types. Events are emitted once per user action or once per relevant page state impression. Events fail gracefully and do not impact user experience if analytics services are unavailable. Event payloads are visible and queryable in PostHog. Event properties conform to the specifications defined in this ticket. my_development_page_viewed  is captured when the My Development page loads successfully. my_development_page_viewed  includes the correct  profile_state  based on whether role, grade, role-based competencies, and self-declared competencies are available. functional_competencies_tooltip_viewed  is captured when the Functional Competencies tooltip is viewed. functional_competencies_expanded  is captured when the officer clicks "View more". manage_competencies_clicked  is captured when the officer clicks either "Manage competencies" or "Add competencies" from the My Development page. explore_new_roles_clicked  is captured when the officer clicks the Explore New Roles CTA. issue_reported  is captured when an officer submits a report issue action from My Development. Product teams are able to build funnels and dashboards for: My Development page adoption Profile data completeness Missing role/grade and competency edge cases Manage Competencies click-through Add Competencies click-through Explore New Roles click-through Issue reporting by issue type Functional competency section engagement  Success Metrics Supported This instrumentation enables measurement of: % officers who view My Development % officers who land in each profile data state % officers with missing role or grade data % officers with missing role-based competencies % officers with no self-declared competencies % officers who click Manage Competencies % officers who click Add Competencies from an empty state % officers who click Explore New Roles % officers who report missing role, grade, or competency data Functional competency tooltip usage Functional competency View More engagement Drop-off from My Development before any development action  Definition of Done All events listed in scope are implemented and visible in PostHog. Event names and properties match the specification. Event payloads are validated in PostHog. All six profile detail edge cases are tested end-to-end. Issue report events use the shared  issue_reported  taxonomy. No direct PII is sent in event payloads. Product team can build adoption, edge case, issue reporting, and CTA conversion dashboards without additional engineering work.
