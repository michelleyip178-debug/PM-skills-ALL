## Description

Background otep-auth (Postgres-backed Keycloak) has fully replaced the legacy keycloak ECS service (embedded H2) across dev, qa, and uat. otep-pocdex is a mock POCDEX service with no active consumers remaining. Both stacks are safe to decommission. Scope live/{env}/compute/ecs/keycloak/ — all 4 envs live/{env}/compute/ecs/keycloak-shared/ — all 4 envs live/{env}/compute/ecs/otep-pocdex/ — all 4 envs live/{env}/compute/ecs/otep-pocdex-shared/ — all 4 envs  Pre-destroy IaC changes required (before any terragrunt destroy) live/{env}/compute/ecs/egress-proxy/terragrunt.hcl (all 4 envs) — remove dependency "keycloak" block and dependency.keycloak.outputs.security_group_id from ingress_security_group_ids. otep-auth is already in that list — no replacement needed. live/{env}/compute/alb/terragrunt.hcl (all 4 envs) — remove the "keycloak" entry from target_groups. Confirm realms_route_target_group_key is already set to "otep-auth" in all envs before touching this. module/compute/ecs/account-setup/main.tf — remove aws_ecr_repository.keycloak and aws_ecr_repository.pocdex (after confirming ECR repos are empty or images are no longer needed).  Destroy order per environment  Apply egress-proxy and alb changes first, then destroy in this order:  keycloak → keycloak-shared  otep-pocdex → otep-pocdex-shared  Do not destroy rds-keycloak or rds-keycloak-shared — otep-auth still depends on them. Acceptance criteria egress-proxy applied cleanly after removing keycloak SG reference (all envs) alb applied cleanly after removing keycloak target group (all envs) terragrunt destroy completes cleanly for all 4 stacks per env aws ecs describe-services confirms services are gone No other stack's terragrunt plan shows new errors after the destroys account-setup applied to remove the ECR repos (or deferred to a follow-up)  Notes prd keycloak destroy is blocked until the prd otep-auth ECR image is pushed and service is confirmed healthy (tracked separately) keycloak-shared in all envs currently also grants Secrets Manager access to rds-keycloak master secret — this policy disappears on destroy but otep-auth-shared already has the same grant, so no impact
