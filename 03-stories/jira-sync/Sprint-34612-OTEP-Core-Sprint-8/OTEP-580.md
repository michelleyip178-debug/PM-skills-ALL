## Description

Analytics Instrumentation – Course Recommendations User Story As a product manager and analyst, I want to track how officers interact with recommended courses so that I can measure whether competency gap recommendations lead officers to explore relevant learning opportunities.  Background / Context Course recommendations are generated based on the competency gaps between an officer's current competency profile and a selected role. The same recommendation component appears in multiple locations: Based on your current role Explore New Roles Saved Target Role (future) This section allows officers to: View recommended courses Browse additional recommended courses through the carousel Click a recommended course to view course details Explore the wider course catalogue Analytics from this section will be used to validate whether competency gap recommendations encourage officers to explore learning opportunities and assess the quality and effectiveness of the course recommendation engine.  Scope In Scope Instrumentation of course recommendation interactions including: Course recommendations returned Course recommendation impressions Course recommendation page changes Course recommendation clicks Explore Courses CTA No course recommendations returned Out of Scope LEARN course detail page analytics Course application and enrolment analytics My Development profile instrumentation Role recommendation instrumentation User identity and person properties (covered in OTEP-488) Session replay  Events 1. course_recommendations_returned Triggered when the recommendation engine successfully returns course recommendations for the selected role. Properties Property Type source_page String source_section String recommendation_count Number course_id Array[String] course_name Array[String] Accepted values for source_page: my_development_page course_landing_page course_discovery_page Accepted values for source_section: based_on_current_role explore_new_roles js_ recommended_for_you Purpose Measure recommendation engine coverage and understand how often relevant course recommendations are successfully generated for a selected role. Capturing the returned course IDs and course names enables analysis of: Most frequently recommended courses Recommendation frequency by course Recommendation click-through rate by course Courses that are frequently recommended but rarely clicked Overall effectiveness of the recommendation engine  2. course_recommendations_impression Triggered when the course recommendation swimlane first enters the officer's viewport. Properties Property Type source_page String source_section String Accepted values for source_page: my_development_page course_landing_page course_discovery_page Accepted values for source_section: based_on_current_role explore_new_roles js_ recommended_for_you Purpose Measure whether officers actually scroll to and view the recommended courses. This distinguishes recommendations that were successfully generated from recommendations that were actually seen by the officer.  3. course_recommendation_page_changed Triggered when an officer navigates to another page within the course recommendation carousel. This event is  not  triggered for the initial page of recommendations. The initial exposure is already captured by  course_recommendations_impression . Properties Property Type source_page String source_section String page_number Number Accepted values for source_page: my_development_page course_landing_page course_discovery_page Accepted values for source_section: based_on_current_role explore_new_roles js_ recommended_for_you Purpose Measure how deeply officers browse recommended courses beyond the initial recommendations. Together with  course_recommendations_impression , this event enables analysis of: Average number of course pages viewed Approximate number of recommended courses viewed Whether officers browse beyond the initial recommendations Course click-through rate relative to recommendation exposure This event intentionally captures content exploration rather than carousel navigation, providing a clearer measure of engagement with recommended learning opportunities.  4. course_recommendation_clicked Triggered when an officer clicks a recommended course card. Properties Property Type source page String source_section String course_rank Number Accepted values for source_page: my_development_page course_landing_page course_discovery_page Accepted values for source_section: based_on_current_role explore_new_roles js_ recommended_for_you Purpose Measure click-through rate for recommended courses and understand whether officers take the next step from competency gap awareness into learning exploration.  5. no_course_recommendations_returned Triggered when no eligible course recommendations are returned for the selected role. Properties Property Type source_page String source_section String Accepted values for source_page: my_development_page course_landing_page course_discovery_page Accepted values for source_section: based_on_current_role explore_new_roles js_ recommended_for_you Purpose Measure recommendation engine gaps and understand how often officers are unable to receive personalised learning recommendations for a selected role.  6. explore_courses_clicked Triggered when an officer clicks the  Explore Courses  CTA. Properties Property Type source_page String source_section String recommendation_state String Accepted values for source_page: my_development_page course_landing_page course_discovery_page Accepted values for source_section: based_on_current_role explore_new_roles js_ recommended_for_you Accepted values for recommendation_state: recommendations_available no_recommendations Purpose Measure whether officers choose to explore the wider course catalogue after viewing recommended learning opportunities. Comparing click-through rates between recommendation states helps determine whether officers prefer browsing all available courses instead of personalised recommendations, and whether the recommendation engine is encouraging or discouraging further exploration.  Acceptance Criteria All events listed in this ticket are instrumented and captured in PostHog. Event names follow the approved analytics taxonomy. Event properties are sent using consistent naming conventions and data types. Events are emitted once per user action or once per relevant recommendation state. Events fail gracefully and do not impact user experience if analytics services are unavailable. Event payloads are visible and queryable in PostHog. Event properties conform to the specifications defined in this ticket. course_recommendations_returned  is captured whenever the recommendation engine returns course recommendations. course_recommendations_impression  is captured when the recommendation swimlane first enters the officer's viewport. course_recommendation_page_changed  is captured whenever the officer navigates to another page within the recommendation carousel. course_recommendation_clicked  is captured whenever an officer clicks a recommended course. no_course_recommendations_returned  is captured whenever no eligible recommendations are available. explore_courses_clicked  is captured whenever the Explore Courses CTA is clicked. Product teams are able to build dashboards and funnels for: Recommendation engine coverage Recommendation visibility Recommendation browsing depth Recommendation click-through rate Recommendation availability by source section Most frequently recommended courses Explore Courses click-through by recommendation state  Success Metrics Supported This instrumentation enables measurement of: % of selected roles that return course recommendations Average number of recommendations returned Most frequently recommended courses Recommendation visibility rate Average number of course pages viewed Approximate number of recommended courses viewed Recommendation click-through rate Recommendation click-through rate by course Average course rank clicked % of selected roles with no recommendations available Explore Courses click-through rate when recommendations are available Explore Courses click-through rate when no recommendations are available Funnel from recommendation display → course recommendations returned → recommendation impression → recommendation browsing → course click  Definition of Done All events listed in scope are implemented and visible in PostHog. Event names and properties match the specification. Event payloads are validated in PostHog. Recommendation returned, recommendation impression, recommendation page changes, course click, no recommendation, and Explore Courses flows are tested end-to-end. No direct PII is sent in event payloads. Product team can build recommendation engine quality, recommendation engagement, recommendation browsing, and course click-through dashboards without additional engineering work.
