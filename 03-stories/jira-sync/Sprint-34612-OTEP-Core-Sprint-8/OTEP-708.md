## Description

User Story As a Product Manager and analyst, I want to track how officers interact with the Course Landing Page so that I can measure the effectiveness of personalised course recommendations and understand how officers transition from the landing page into course discovery.  Background / Context The Course Landing Page is the primary entry point into the Learning & Courses experience. Officers can: Browse personalised course recommendations through the  Recommended for you  swimlane. Search for courses using the search bar. Navigate to the Course Discovery Page by clicking  Explore all courses . Recommendation generation and recommendation engagement for the  Recommended for you  swimlane are instrumented separately under  Analytics - Course Recommendations   (   )  Scope In Scope Instrumentation of: Course search Search autocomplete selection Explore all courses CTA Out of Scope Course recommendation instrumentation (covered under  Analytics - Course Recommendations  ) Course Discovery Page instrumentation Course Detail Page instrumentation LEARN platform analytics User identity and person properties (covered separately) Session replay  Events 1. course_search_performed Triggered when a course search is executed from the Course Landing Page. Properties Property Type source_page String search_term String autocomplete_used Boolean Accepted values for  source_page course_landing_page Purpose Measure search behaviour on the Course Landing Page and understand whether officers use search as their preferred entry point into the course catalogue. Supports analysis of: Most common search terms Landing page search adoption Search vs recommendation usage  2. course_search_autocomplete_selected Triggered when an officer selects an autocomplete suggestion from the Course Landing Page search bar. Properties Property Type source_page String search_term String selected_value String autocomplete_category String Accepted values for  source_page course_landing_page course_discovery_page Accepted values for  autocomplete_category course domain Purpose Measure autocomplete adoption and understand whether officers rely on autocomplete suggestions instead of completing a free-text search. Supports analysis of: Autocomplete adoption rate Most frequently selected autocomplete suggestions Distribution of course vs domain selections  3. explore_all_courses_clicked Triggered when an officer clicks the  Explore all courses  CTA. Properties Property Type source_page String recommendation_state String Accepted values for  source_page course_landing_page Accepted values for  recommendation_state recommendations_available no_recommendations (will almost never happen unless JS API fails) Purpose Measure whether officers choose to continue exploring the wider course catalogue from the Course Landing Page. Comparing click-through rates between recommendation states helps determine whether personalised recommendations encourage further exploration or whether officers prefer browsing the full course catalogue. 4. course_landing_page_viewed [added 27 Aug] Triggered when the course landing page successfully loads Properties No additional properties required. Purpose Measure adoption of the Course Landing Page and establish the starting point for analysing how officers engage with course recommendations, search, and the wider course catalogue. Supports analysis of: Number and % of officers who view the Course Landing Page Landing Page → recommended course click conversion Landing Page → search conversion Landing Page → Explore all courses conversion Drop-off from Landing Page view to subsequent course discovery actions   Acceptance Criteria All events listed in this ticket are instrumented and captured in PostHog. Recommendation instrumentation implemented under  Analytics - Course Recommendations   remains unchanged and continues to capture recommendation generation, recommendation impressions, recommendation carousel interactions, recommendation clicks, recommendation availability, and recommendation state for the  Recommended for you  swimlane. Event names follow the approved analytics taxonomy. Event properties use consistent naming conventions and data types. Events are emitted once per user action. Events fail gracefully and do not impact user experience if analytics services are unavailable. Event payloads are visible and queryable in PostHog. Event properties conform to the specifications defined in this ticket. course_search_performed  is captured whenever an officer executes a search from the Course Landing Page. course_search_autocomplete_selected  is captured whenever an autocomplete suggestion is selected from the Course Landing Page search bar. explore_all_courses_clicked  is captured whenever the  Explore all courses  CTA is clicked. Product teams are able to build dashboards and funnels for landing page search behaviour and transition into the Course Discovery Page.  Success Metrics Supported This instrumentation enables measurement of: Landing page search adoption rate Most common landing page search terms Autocomplete adoption rate Most frequently selected autocomplete suggestions Explore all courses click-through rate Explore all courses click-through rate by recommendation state Funnel from Landing Page → Search Funnel from Landing Page → Course Discovery Page  Definition of Done All events listed in scope are implemented and visible in PostHog. Event names and properties match the specification. Event payloads are validated in PostHog. Search, autocomplete, and  Explore all courses  flows are tested end-to-end. Recommendation instrumentation under  Analytics - Course Recommendations   continues to function as specified. No direct PII is sent in event payloads. Together with  Analytics - Course Recommendations  , the Product team can build complete dashboards covering Course Landing Page discovery, recommendation engagement, search behaviour, and transition into the Course Discovery Page without additional engineering work.
