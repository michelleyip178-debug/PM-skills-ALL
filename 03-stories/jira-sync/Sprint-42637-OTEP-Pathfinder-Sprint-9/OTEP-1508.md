## Description

Rebuild did not bu mp the toolchain or base image. otep-web image CVEs  Partial Rebuilt 2 Sep 10:34 (cd58c8ce) but npm bundle still present (16 high) and Node still bundles openssl 3.5.7, which gained 2 newly disclosed criticals (CVE-2026-63073, CVE-2026-75803; fixed in Alpine openssl 3.5.8-r0). We should review our images and upgrade them.   otep-web  was using the latest  24.19-alpine3.24  from docker hub.   Last week another version was publish  24.20.alpine3.24 :      But this still has the same vulns.   otep-service  is using a custom image based on the COE image. This base image receive some updates but we have to manually rebuild and store a custom base image since the COE team does not keep versioned images and only have  latest  available which make it difficult for us to have a reproducible build.   Latest image  go  version is also not in sync with ours so we’ll have to be mindful, especially since their commit history does not match the actual  Dockerfile :  https://sgts.gitlab-dedicated.com/innersource/projects/sgts-pipelinecoe/containers/go-container/-/blob/2889e185d7249e10fe0630268fb8134b83238b0c/Dockerfile  Our rebuild version is also single architecture (x64) which cause some slowness in our local dev setup. Ideas: For  otep-web , we need to bump the image to the next minor version. We could/should remove npm from the runtime image as we only need node and the standalone files.   For  otep-service , we could rebuild the base image (last build was 3+month ago) if we can validate that the go version update does not impact anything.   Alternatively we could consider docker hardened images:      This used to be a docker paid offering but was shifted to  Apache 2.0 license  in 2025 and images are now free to use (except some images with specific compliance requirements like  fips  or  stig ).
