# OTEP-1507: Implement HTTP Security Headers in next.config.ts

**Status:** Done
**Assignee:** Thomas Huchedé
**Story Points:** N/A
**Sprint:** OTEP-Pathfinder Sprint 9 (42637)

---

## Description

Description  In  otep-web ,  next.config.ts  does not define standard defense-in-depth HTTP security headers. Adding these headers mitigates risks such as cross-site scripting (XSS), clickjacking, MIME-type sniffing, and unintended credential exposure.  Affected Files next.config.ts   Acceptance Criteria Configure the  headers()  async function in  next.config.ts  to attach the following response headers across all routes ( source: '/(.*)' ):  ⚬  Content-Security-Policy  ⚬  X-Frame-Options  (set to  DENY  or  SAMEORIGIN )  ⚬  X-Content-Type-Options  (set to  nosniff )  ⚬  Referrer-Policy  (set to  strict-origin-when-cross-origin )  ⚬  Permissions-Policy  ⚬  Strict-Transport-Security  (HSTS) Verify that HTTP response headers are present using browser DevTools or  curl -I . Ensure existing web application functionality is unaffected by the updated header policies.
