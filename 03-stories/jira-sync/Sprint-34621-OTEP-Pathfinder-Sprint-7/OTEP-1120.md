## Description

Below is the  Build brief  provided by     Context Pathfinder features keep breaking in the shared dev environment due to deployments and config changes made by other squads. This suite is our tripwire: it runs on a schedule against the DEPLOYED environment and alerts within an hour that something broke, and at which layer. Design goal: a red run must be  attributable  — auth failures distinguishable from feature failures, and feature failures from data failures. Scope In scope (Pathfinder-owned): Opportunity Listing ( /opportunities ): search, filter, sort, pagination Opportunity Detail ( /opportunities/[id] ): OTG-sourced and Careers@Gov-sourced, apply flows, closed state CFT Admin File Upload ( /my-admin/upload ): access control and upload flow otep-service  API endpoints backing the above (direct API tests) Out of scope:  competency, profile, course, role recommendation, provisioning (Core team features) Architecture — 3 layers, cheapest first Layer Type Purpose 1 HTTP probes (no browser) Classify platform failures before feature tests 2 API tests (no browser) Verify contract the UI depends on 3 UI E2E (Playwright) User journeys through deployed frontend Pipeline stops reporting at the first failing layer. Test Case Inventory Layer 2: API (11 tests) A1:  /health  returns 200 (P0) A2:  /api/v1/opportunities  without token returns 401 (P0) A3:  /api/v1/opportunities  with token returns 200, count > 0 (P0) A4: type filters return only matching items (P0) A5: search returns results; >256 chars returns validation error not 500 (P1) A6: sort_by=closing_date ordered; garbage returns 4xx not 500 (P1) A7: pagination works; edge cases handled gracefully (P1) A8: GET single opportunity by ID returns 200 with type.code (P0) A9: GET random UUID returns 404 not 500 (P1) A10: CAG data freshness — max updated_at < 48h (P0) A11: POST opportunity-sync + poll to completion (FULL only) Layer 3: UI Listing (8 tests) L1–L8: listing loads, search, type filters, combined filters, sort, pagination, garbage params, long search term Layer 3: UI Detail (7 tests) D1–D7: card navigation, C@G apply, FormSG apply, apply new tab, closed opportunity, unknown ID, ms= param Layer 3: UI Upload (4 tests) U1: Admin sees upload form (P0) U2: Non-admin sees "Not authorised" (P0) U3: Unauthenticated redirects to login (P1) U4: Full upload round trip (FULL only) Layer 1 + Auth (3 tests) P1a: Base URL, Keycloak, service health probes (P0) P2a: auth.setup succeeds for user and admin (P0) P3a: Unauthenticated visit redirects to Keycloak (P1) Prerequisites [ ] Create two Keycloak test accounts in dev realm (non-admin + admin in ADMIN_EMAILS) [ ] Add CI masked variables:  PATHFINDER_BASE_URL ,  PATHFINDER_SERVICE_URL ,  PATHFINDER_KEYCLOAK_URL ,  PATHFINDER_TEST_USER/PASS ,  PATHFINDER_ADMIN_USER/PASS [ ] Create  fixtures/upload-smoke.xlsx  (<100KB) Conventions Selectors:  getByRole ,  getByLabel ,  getByPlaceholder  — no invented data-testid All files under  e2e/pathfinder/  with dedicated  playwright.pathfinder.config.ts Retries 2 on CI, trace retain-on-failure, single worker API tests use Playwright request fixture with Keycloak password grant token Definition of Done All P0 tests green for 3 consecutive scheduled runs against dev Sabotage test: wrong Keycloak URL reports identity-layer failure without running feature specs P0 runtime under 5 minutes README updated with: how to run locally, how to add a spec, calibration log
