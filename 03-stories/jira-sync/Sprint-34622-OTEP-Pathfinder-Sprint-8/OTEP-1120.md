## Description

Below is the  Build brief  provided by     Context Pathfinder features keep breaking in the shared dev environment due to deployments and config changes made by other squads. This suite is our tripwire: it runs on a schedule against the DEPLOYED environment and alerts within an hour that something broke, and at which layer. Design goal: a red run must be  attributable  — auth failures distinguishable from feature failures, and feature failures from data failures. Scope In scope (Pathfinder-owned): Opportunity Listing ( /opportunities ): search, filter, sort, pagination Opportunity Detail ( /opportunities/[id] ): OTG-sourced and Careers@Gov-sourced, apply flows, closed state CFT Admin File Upload ( /my-admin/upload ): access control and upload flow otep-service  API endpoints backing the above (direct API tests) Out of scope:  competency, profile, course, role recommendation, provisioning (Core team features) Architecture — 3 layers, cheapest first Layer Type Purpose 1 HTTP probes (no browser) Classify platform failures before feature tests 2 API tests (no browser) Verify contract the UI depends on 3 UI E2E (Playwright) User journeys through deployed frontend Pipeline stops reporting at the first failing layer. Test Case Inventory Layer 2: API (11 tests) A1:  /health  returns 200 (P0)     A2:  /api/v1/opportunities  without token returns 401 (P0)  A3:  /api/v1/opportunities  with token returns 200, count > 0
