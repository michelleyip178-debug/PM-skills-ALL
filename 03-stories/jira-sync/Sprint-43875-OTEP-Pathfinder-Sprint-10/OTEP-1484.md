# OTEP-1484: Update Opportunity competency matching to include the new officer_self_competency table

## Description

Description  Following the recent database schema change, self-added competencies were migrated from  officer_competency  to a dedicated  officer_self_competency  table. As a result, the Opportunity matching logic is no longer evaluating user-added competencies. When a user adds or deletes an additional competency on the Home page, this change needs to correctly reflect in the Opportunity listings so the user sees an accurate match state. Acceptance Criteria Opportunity Card Matching:  The "X/Y competencies matched" metric on the Opportunity listing card must update to include competencies found in the user's  officer_self_competency  records. Opportunity Details Rendering:  The requirement tags on the Opportunity details page must correctly display a checkmark/matched state if the user possesses that competency in either their core/functional table or their self-added table. Dynamic Updates:  Adding or deleting a self-added competency on the Home page must instantly reflect on the Opportunities page upon navigation Deduplication:  (Handled before writing to the table ) The matching logic must handle cases gracefully where a competency might theoretically exist in both tables, ensuring the match count does not exceed the total required competencies. Technical Implementation Notes Update the backend query or resolver responsible for Opportunity matching to evaluate both  officer_competency  (for system-assigned Core/Functional competencies) and  officer_self_competency  (for user-added competencies). Ensure the data aggregation combines these two sources before comparing them against the target Opportunity's required competencies.
